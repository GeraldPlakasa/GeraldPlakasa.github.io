The Problem

Ribuan Well Log Masih di Kertas

Arsip well log lapangan legacy Sumatera Selatan tersimpan sebagai scan kertas (TIFF, PDF, JPG lawas), banyak yang faint, miring, dan penuh noise gridline. Data ini nyaris tidak bisa dipakai untuk analisis modern selama masih berupa gambar.

Inti masalahnya: tracing kurva yang gampang itu bukan bottleneck-nya. Yang susah adalah kalibrasi (depth + value axis) dan kurva-kurva sulit, salah kalibrasi bikin tracing sempurna jadi tidak berguna.

Karena ini data subsurface yang sensitif, semua harus jalan lokal/on-prem. Tidak boleh ada yang lewat public API.

What It Does

Dari Raster ke LAS

Well-D mengambil raster scan dan menghasilkan file LAS 2.0 (plus CSV/Excel) lengkap dengan metadata provenance, dengan manusia tetap di loop untuk QC.

  • Multi-format ingest: TIFF/PDF/PNG/JPG, termasuk multipage TIFF dan scan setinggi 83.000 baris (satu file 293 MB), auto deskew + denoise + CLAHE
  • Kalibrasi axis: depth dan value axis (linear atau logaritmik) dikalibrasi eksplisit sebelum nilai dipercaya
  • Curve tracing: ekstraksi kurva per-track dengan overlay balik ke raster asli untuk verifikasi visual
  • Confidence-aware QC: interval broken/overlap/off-scale ditandai, tidak pernah diam-diam di-interpolasi
  • Error reporting: menampilkan NRMSE + R2 vs ground truth, shape NRMSE untuk besar error, R2 untuk apakah pola wiggle benar-benar cocok
  • Export lengkap: LAS 2.0 via lasio, CSV, Excel, plus sidecar metadata
Architecture

Pipeline Linear, Tiap Stage Independen

Dirancang sebagai pipeline stage yang independen dan bisa dites terpisah, supaya implementasi classical bisa di-swap ke ML tanpa membongkar ulang pipeline.

  • Ingest: load PDF→image ≥300 DPI, split multipage, deskew, denoise, CLAHE
  • Header OCR: Tesseract / EasyOCR / PaddleOCR baca well info dan scale
  • Grid & kalibrasi: deteksi gridline, bangun map depth(pixel_y) + value(pixel_x, track)
  • Extract: classical (threshold + skeletonize + connected components), ML menyusul
  • Vectorize: mask → (depth, value), resample ke depth step reguler, flag gap
  • QC: overlay kurva ke raster, scoring confidence per-interval
  • Export: LAS 2.0 + CSV/Excel + metadata provenance

Backend FastAPI, frontend React web app. Data contract antar-stage pakai pydantic (CurveSpec, TrackSpec, LogHeader, DigitizedCurve); CLI pakai typer. Dua mode: Full-auto (satu klik) dan Assistant (user isi well info + depth range).

Design Principles

Aturan yang Tidak Boleh Dilanggar

Lima prinsip yang mengatur setiap modul, ini requirement, bukan marketing.

  • Human-in-the-loop: setiap kurva hasil tracing wajib bisa di-overlay ke raster asli dan bisa diedit manual
  • Calibration-first: depth dan value axis dikalibrasi dulu sebelum ada nilai yang dipercaya
  • Confidence-aware: interval low-confidence ditandai, tidak pernah diam-diam diisi
  • No silent automation: hasil tidak pernah disajikan sebagai pasti; error vs ground truth selalu ditampilkan
  • Per-track processing: diproses track-by-track, satu gambar bukan satu kurva
Engineering Highlights

Bagian yang Bikin Ini Susah

Beberapa masalah yang diselesaikan lewat iterasi panjang dan divalidasi terhadap 16 pasang ground-truth.

  • Anchor-free ink-Viterbi tracer: shortest-path Viterbi (satu x per baris, penalti smoothness) di atas cost map darkness ternormalisasi, tembus GR NRMSE ~0.07 tanpa klik, tanpa model, mematahkan asumsi "classical auto sudah mentok"
  • RANSAC depth calibration: depth di-fit dari label OCR pakai RANSAC, jadi satu misread tidak merusak kalibrasi seluruh log
  • Log-axis value calibration: track resistivity hampir selalu log; salah handle ini fatal, jadi log + per-decade wrap diarsitek dari awal
  • U-Net fine-tuning pipeline: Dice+BCE, checkpoint safetensors, jalur menuju ekstraksi tanpa manusia (SAM juga dieksplor, diukur jujur)
  • Diagnosa jujur: shape NRMSE bisa menyembunyikan blind spot pada kurva low-variance, dilaporkan bareng R2 supaya ketahuan mana yang benar-benar cocok vs cuma "aman"
